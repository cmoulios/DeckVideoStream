- `AVURLAsset` on the `qt`-brand FRV with its ALAC track opens the video
  track normally; `canProvideSampleCursors` is true; a full cursor pass over
  the track costs ~15 ms for a 4–5 minute file. No audio device is involved
  (no player is ever created).
- Matches the earlier `ffprobe` numbers (median ≈2 s, worst ≈7 s GOPs).

**Gotcha found and fixed:** `AVSampleCursor.presentationTimeStamp` is on the
track's *media* timeline; `AVAssetReader` output (and AVPlayer, and the audio
position) is on the *asset* timeline after the edit list. Every
YouTube-sourced H.264 file here carries a one-frame edit hiding the B-frame
delay, so the raw cursor table was exactly one frame late (`reorder` showed
379/379 mismatches). `FrameTable.build` now maps media → asset time through
`AVAssetTrack.segments` (`timeMapping`); samples outside every edit are
dropped. After the fix: 0 mismatches on all files.

## S1 Throughput (sequential decode from 0, whole file)

| file | format | 1 stream | 2 streams aggregate |
|---|---|---|---|
| 1080p | BGRA8 | 455 fps (19× realtime) | 1007 fps (503/stream) |
| 1080p | NV12 | **1721 fps (72× realtime)** | 1724 fps (862/stream) |
| 480p | BGRA8 | 900 fps | 3056 fps |
| 480p | NV12 | 5497 fps | 8457 fps |

- BGRA's cost is the YUV→RGB pixel-transfer pass, not the decoder: BGRA
  scales with a second stream (conversion is per-stream serial work), NV12
  does not (the hardware decoder is the ceiling at ~1700 fps 1080p).
- Two decks at 24–30 fps need ~60 fps of decode; even eight channels at
  1080p are <15% of the NV12 ceiling. Decode-ahead is essentially free.

## S2 Cold access (jump into the worst 7 s GOP, frames 1938..<2106)

Reader restart mode (new `AVAssetReader` per jump), median of 10 trials,
time from "decide to jump" to "target frame in hand":

| offset into GOP | BGRA8 | NV12 | create+start (both) |
|---|---|---|---|
| +0 frames (keyframe) | 24 ms | 21 ms (14 ms with exact-index start) | 8–12 ms |
| +41 frames | 39 ms | 30 ms | |
| +83 frames | 55 ms | 47 ms | |
| +167 frames (end of GOP) | 89 ms | 87 ms | |

`supportsRandomAccess` + `reset(forReadingTimeRanges:)` mode: retarget costs
0.05 ms instead of ~10 ms create+start (12 / 21 / 39 / 75 ms), but requires
draining the current range first, so it is not usable for abrupt jumps.
**Decision: restart mode**; the 10 ms is noise next to the GOP prefix.

- The reader emits the exact target frame first (0 frames before target,
  +0.000 s) at every offset once the start time is built from the table's
  integer PTS (`start(atIndex:)`); building it from seconds could land one
  tick early and vend the previous frame.
- Prefix decode runs at ~0.45 ms/frame (frames decoded but never
  converted/emitted). Worst case on this library: ~90 ms for a jump to the
  last frame of a 7 s GOP. Today's per-frame zero-tolerance seek pays a
  comparable prefix on *every* displayed frame; the library pays it once per
  discontinuity.
- First trial after process start shows a 110–145 ms outlier (cold decoder
  session); steady-state p90 is within 2 ms of the median.

## S6 Memory (pin 200 decoded 1080p frames)

| format | expected (w·h·bpp) | CVPixelBufferGetDataSize sum | system memory delta while held |
|---|---|---|---|
| BGRA8 | 1582 MB | 1582 MB | wired +460 MB, active +800 MB |
| NV12 | 593 MB | 598 MB | active +565 MB |

- Accounting by `count × CVPixelBufferGetDataSize` is exact (row padding is
  nil at 1920 wide). All memory returns to baseline within 0.5 s of release.
- **IOSurface memory is not charged to the process.** `phys_footprint`
  moved 5 MB for 1.58 GB of surfaces; the `footprint` tool lists the 215
  IOSurface regions but attributes 0 B. The memory is real and system-wide
  (`vm_stat` wired/active). Consequences: the library must do its own byte
  accounting (it can, exactly), the DispatchSource memory-pressure signal
  is the right backstop, and Activity Monitor / the app's footprint will
  *understate* video RAM — the strain log must print `residentBytes`.
